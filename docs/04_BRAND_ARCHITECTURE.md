# ORDVELA — Brand Architecture

## Master Brand

**ORDVELA**

The master brand owns the strategic territory. Products and capabilities should inherit the master brand where useful.

## Approved Working Extensions

| Extension | Intended territory |
|---|---|
| Ordvela Systems | business systems / infrastructure |
| Ordvela Platform | broader platform offering |
| Ordvela Intelligence | AI / intelligence layer |
| Ordvela Studio | product/building environment |
| Ordvela API | API and integration layer |
| Ordvela Labs | experimental R&D |
| Ordvela Marketplace | marketplace territory |
| Ordvela Pay | payment territory, subject to regulatory/business validation |

These are architecture candidates, not claims that each product currently exists.

## Naming Rules

1. Use `Ordvela` consistently in the master-brand layer.
2. Prefer descriptive extensions over arbitrary new brands.
3. Do not create a new sub-brand when an extension can communicate the product clearly.
4. A product can later become an independent brand only when there is a documented strategic reason.
5. Do not use an extension publicly until its domain, legal, product, and market requirements have been checked.

## Example Relationship

`ORDVELA` → `Ordvela Systems` → individual product/service

`ORDVELA` → `Ordvela Intelligence` → AI capabilities

`ORDVELA` → `Ordvela Studio` → creation/building environment

## Future Rule

Architecture must remain flexible enough to support software products, services, infrastructure, and future ventures without forcing every activity into the same product label.
